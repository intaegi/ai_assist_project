# UIテスト用資料

すべて架空の会社、サービス、金額で作成したテスト専用資料です。実業務には使用しないでください。

## 初期設定用

`initial_settings/` のMarkdownは、UI-00「初期設定」から基準資料として登録できます。

| ファイル | カテゴリ | 決裁種類 | 資料種別 |
|---|---|---|---|
| `it_payment_policy.md` | 開発・IT | 支払 | 決裁規程 |
| `finance_payment_policy.md` | 経理・購買 | 支払 | 決裁規程 |
| `sales_purchase_policy.md` | 営業 | 購入 | 決裁規程 |
| `standard_approval_template.md` | 任意 | 任意 | 標準様式 |

## 新規決裁アップロード用

`upload/` には原本Markdown、`pdf/` には画面アップロード用PDFを配置します。

| テストシナリオ | 使用ファイル |
|---|---|
| IT年間SaaS正常系 | `TC-DOC-01`、`TC-DOC-02`、`TC-DOC-03` |
| IT請求書不足 | `TC-DOC-02`だけを使用 |
| 経理支払正常系 | `TC-DOC-04` |
| 営業タブレット購入 | `TC-DOC-05` |
| 金額不一致資料 | `TC-DOC-04`と`TC-DOC-06` |
| 取引先不一致資料 | `TC-DOC-01`と`TC-DOC-07` |
| 利用期間不一致資料 | `TC-DOC-01`と`TC-DOC-08` |

## 注意

- Local modeではルールベースの簡易抽出を使用します。
- Local modeでも、取引先、サービス名、金額、利用期間、書類種類を抽出します。
- 必要書類が不足している場合は、`不足・注意`とチェックリストに不足書類が表示されます。
- 金額、取引先、製品・サービス名、利用期間が複数書類間で一致しない場合は、
  Azure OpenAIの回答に依存せず、バックエンドの照合処理で警告します。
- 結果画面の`書類間の記載内容比較`で、AI決裁フォーム値と各書類の値を項目別に確認します。
