# 결재 RAG MVP UI 테스트 항목서

## 1. 문서 목적

이 문서는 결재 RAG MVP를 화면에서 조작하며 기능을 확인하기 위한 수동 테스트 항목서이다.
테스트 데이터는 모두 가상의 회사명, 서비스명, 금액으로 작성되었으며 실무 데이터가 아니다.

테스트 범위:

- 초기 설정 등록
- 신규 결재 생성
- PDF 문서 추출과 필수서류 판정
- 생성 결과 확인과 자동 저장
- 추가 채팅을 통한 재생성
- 작성 이력 조회와 신규 작성 복사
- 오류 및 미지원 범위 확인

## 2. 테스트 실행 방법

### 2.1 권장 순서

1. `Smoke` 테스트로 서버와 기본 화면을 확인한다.
2. `초기 설정` 테스트로 카테고리별 기준을 준비한다.
3. `신규 작성` 정상계와 누락계를 실행한다.
4. `결과 수정`, `이력`, `복사` 테스트를 실행한다.
5. Local mode 완료 후 Azure mode 통합 테스트를 별도로 실행한다.

### 2.2 결과 기록 기준

| 상태 | 의미 |
|---|---|
| PASS | 실제 결과가 기대결과와 일치 |
| FAIL | 실제 결과가 기대결과와 불일치 |
| BLOCKED | 환경 또는 선행조건 문제로 실행 불가 |
| NOT RUN | 아직 실행하지 않음 |

각 테스트에는 다음을 기록한다.

- 실행일과 실행자
- 실제 결과
- PASS/FAIL/BLOCKED
- 화면 캡처 파일명
- FAIL인 경우 이슈 번호와 재현 조건

화면 캡처 파일명 예:

```text
TC-UI-005_step05_20260614.png
```

## 3. 테스트 환경

### 3.1 Local mode 실행

터미널 1:

```powershell
lecture\Scripts\Activate.ps1
$env:APP_STORAGE_MODE="local"
uvicorn backend.app.main:app --reload --port 8000
```

터미널 2:

```powershell
lecture\Scripts\Activate.ps1
$env:APP_STORAGE_MODE="local"
streamlit run frontend/app.py --server.port 8501
```

접속 주소:

- Streamlit: `http://localhost:8501`
- FastAPI 문서: `http://localhost:8000/docs`
- 헬스 체크: `http://localhost:8000/health`

### 3.2 테스트 데이터 초기화

Local mode 데이터는 `data/database.json`과 `data/files/`에 저장된다.
반복 테스트 시 기존 `data/`를 먼저 백업하고, 깨끗한 테스트가 필요할 때만 서버를 종료한 후 초기화한다.

## 5. 테스트 케이스

### TC-UI-001 서버 실행과 초기 화면

분류: Smoke

사전조건:

- FastAPI와 Streamlit이 Local mode로 실행 중이다.

조작순서:

1. `http://localhost:8501`에 접속한다.
2. 왼쪽 사이드바를 확인한다.
3. 기본 표시 화면을 확인한다.

기대결과:

1. Python 예외 화면 없이 앱이 표시된다.
2. 사이드바에 `新規作成`, `初期設定`, `作成履歴`가 표시된다.
3. 메인 영역에 `新規決裁作成`과 `AI決裁案を作成` 버튼이 표시된다.
4. 일반 사용자 화면에 Backend 또는 AI Search 연결 상태가 상시 표시되지 않는다.

증적: 초기 화면 전체 캡처

### TC-UI-002 기본 입력·서류 기준 확인

분류: 초기 설정

조작순서:

1. 사이드바에서 `初期設定`을 선택한다.
2. `入力・書類基準` 탭을 연다.
3. 업무 카테고리 `開発・IT`, 결재 종류 `支払`을 선택한다.
4. 필수 입력 항목, 필요서류, 조건부서류를 확인한다.

기대결과:

1. 초기 설정 화면으로 전환된다.
2. 필수 입력 항목의 기본 예가 표시된다.
3. 필요서류에 `請求書`를 지정할 수 있다.
4. 조건부서류를 `見積書|新規契約または10万円以上の場合` 형식으로 지정할 수 있다.

증적: 입력·서류 기준 탭 캡처

### TC-UI-003 기준 설정 저장

분류: 초기 설정

조작순서:

1. 업무 카테고리 `開発・IT`, 결재 종류 `支払`을 선택한다.
2. 필수 입력 항목에 목적, 거래처, 서비스명, 금액을 입력한다.
3. 필요서류에 `請求書`를 입력한다.
4. 조건부서류에 `見積書|新規契約または10万円以上の場合`을 입력한다.
5. `基準設定を保存`을 누른다.
6. 신규 작성 화면에서 같은 카테고리와 종류를 선택한다.

기대결과:

1. `基準設定を保存しました。`가 표시된다.
2. 신규 작성의 `作成前の準備事項`에 저장한 필수 항목과 필요서류가 표시된다.

증적: 저장 성공 메시지와 신규 작성 준비사항

### TC-UI-004 기준 자료 등록과 인덱스 갱신

분류: 초기 설정

사전조건:

- Local mode와 Azure mode 중 어느 환경을 테스트하는지 먼저 기록한다.
- Local mode에서는 Azure Portal에 Blob, Cosmos DB, AI Search 데이터가 생성되지 않는다.

조작순서:

1. `初期設定`의 `基準資料` 탭을 연다.
2. 대상 카테고리 `開発・IT`, 결재 종류 `支払`을 선택한다.
3. 자료 종류 `決裁規程`을 선택한다.
4. 제목에 `開発・IT支払決裁基準`을 입력한다.
5. SET-01을 업로드하고 `資料を登録`을 누른다.
6. 등록 완료 후 초기화된 등록 폼에서 대상 카테고리와 결재 종류를 다시 선택한다.
7. `資料種別` 라디오에서 `標準様式`을 선택한다.
8. 제목에 `決裁申請標準記載様式`을 입력하고 SET-04를 업로드해 등록한다.
9. `検索インデックスを更新`을 누른다.

기대결과:

1. 기준 자료는 한 번에 한 건씩 등록된다.
2. `資料種別`에 `決裁規程`, `標準様式`, `必要書類基準`, `サンプル過去決裁`가 라디오로 항상 표시된다.
3. 자료 제목을 비우면 업로드 파일명이 제목으로 자동 사용된다.
4. 파일을 선택하면 `資料を登録` 버튼으로 등록할 수 있다.
5. 각 업로드 후 `資料を登録しました。`가 표시되고 등록 폼이 초기화된다.
6. Local mode에서는 `Local mode`와 Azure AI Search로 전송되지 않았다는 메시지가 표시된다.
7. Local mode에서 갱신 버튼을 반복해도 검색 대상 건수가 계속 증가하지 않는다.
8. Azure mode에서는 `Azure AI Searchへ登録しました`가 표시되고 전용 인덱스에 문서가 등록된다.
9. `接続確認`에는 실제 Storage Account, 컨테이너, Search 인덱스명이 표시된다.
10. Search 등록 방식은 SDK 직접 업로드이므로 전용 Data source, Indexer, Skillset은 생성되지 않는다.

증적: 자료 등록과 인덱스 갱신 결과

### TC-UI-005 개발·IT SaaS 지급 정상계

분류: 신규 작성 / 정상계

테스트 데이터: TC-DOC-01, TC-DOC-02, TC-DOC-03

조작순서:

1. `新規作成`을 선택한다.
2. 업무 카테고리 `開発・IT`, 결재 종류 `支払`을 선택한다.
3. 목적에 `開発チームで利用するCloudGuard Proの年間利用料を支払います。`를 입력한다.
4. 세 개의 PDF를 모두 업로드한다.
5. `AI決裁案を作成`을 누른다.
6. 생성 결과의 원본, 폼, `要約` 영역의 비교표·부족·주의·체크리스트를 확인한다.

기대결과:

1. 생성 중 상태가 표시된 후 결과 화면으로 이동한다.
2. 거래처에 `株式会社ネクストクラウド`가 추출된다.
3. 서비스명에 `CloudGuard Pro 年間ライセンス`가 추출된다.
4. 금액에 `132000`이 표시된다.
5. 청구서 누락 오류가 표시되지 않는다.
6. 왼쪽에서 업로드 PDF를 선택해 미리 볼 수 있다.
7. 오른쪽 폼에서 생성 결과를 직접 수정할 수 있다.
8. `書類間の記載内容比較`에서 세 서류의 거래처, 서비스명, 금액, 이용 기간이 `一致`로 표시된다.
9. 체크리스트에 원본 대조 항목이 표시된다.

증적: 결과 화면 전체, `要約` 영역의 비교표·부족·주의·체크리스트

증적: 부족·주의 탭

### TC-UI-010 생성 폼 자동 저장

분류: 결과 수정

사전조건:

- TC-UI-005 결과 화면이 표시되어 있다.

조작순서:

1. 거래처 또는 결재 본문을 수정한다.
2. 다른 입력 항목을 클릭해 변경을 확정한다.
3. 사이드바에서 다른 화면으로 이동한다.
4. 작성 이력에서 같은 건을 다시 연다.

기대결과:

1. 입력 변경 후 `自動保存しました`가 표시된다.
2. 별도의 편집, 임시저장, 저장, 작성완료 버튼이 없다.
3. 이력을 다시 열었을 때 수정값이 유지된다.

증적: 자동 저장 메시지와 재조회 값

### TC-UI-011 추가 채팅 재생성

분류: 결과 수정

조작순서:

1. 결과 화면 하단 `AIへの修正依頼`에 `決裁本文を承認者向けに3文以内へ短縮してください。`를 입력한다.

증적: 수정 본문과 수정 이력

### TC-UI-013 과거 이력을 신규 작성으로 복사

분류: 이력

조작순서:

1. 작성 이력에서 TC-UI-005 건을 연다.
2. `新規作成へコピー`를 누른다.
3. 신규 작성 화면의 입력값과 첨부파일 안내를 확인한다.
4. 목적과 금액을 수정하고 `AI決裁案を作成`을 누른다.

기대결과:

1. 신규 case ID가 생성된다.
2. 과거 입력값과 첨부파일이 복사된다.
3. 날짜, 금액, 이용기간, 첨부서류를 재확인하라는 안내가 표시된다.
4. 복사 원본의 이력은 변경되지 않는다.
5. 새 건의 결과와 버전이 별도로 저장된다.

증적: 복사 후 신규 작성 화면과 새 결과

### TC-UI-014 기타 카테고리 입력 검증

3. 기준이 없으면 담당 부문 확인이 필요하다는 안내가 표시된다.

### TC-UI-015 백엔드 연결 실패

### TC-UI-016 문서 간 금액 불일치 경고

분류: 신규 작성 / 불일치 검증

테스트 데이터: TC-DOC-04, TC-DOC-06

조작순서:

2. 결재안을 생성한다.
3. `書類間の記載内容比較`, `不足・注意`, `チェックリスト`를 확인한다.

기대결과:

2. 비교표에서 청구서 `88,000円`, 견적서 `99,000円`이 표시되고 `差異あり`로 판정된다.

증적: 두 원본, 비교표, 부족·주의, 체크리스트

### TC-UI-017 Azure 연결 확인

분류: Azure 통합

사전조건:

- 노출된 기존 키를 재발급했다.
- `.env`에 Azure OpenAI, AI Search, Blob Storage 설정을 입력했다.
- Cosmos DB를 사용할 경우 Cosmos 설정을 입력하고, 보류할 경우 `AZURE_COSMOS_ENABLED=false`로 설정했다.
- `python -m scripts.bootstrap_azure`가 완료되었다.

조작순서:

1. `APP_STORAGE_MODE=azure`로 FastAPI와 Streamlit을 실행한다.
2. `初期設定`의 `接続確認` 탭을 연다.
3. Blob, Search, OpenAI, Cosmos 또는 로컬 이력 저장 상태를 확인한다.
4. TC-UI-004와 TC-UI-005를 다시 실행한다.

기대결과:

1. Blob, Search, OpenAI는 정상으로 표시된다.
2. 접속 확인에 실제 Storage Account, 4개 컨테이너, `.env`의 Search 인덱스명이 표시된다.
3. 기준 자료가 `.env`의 `AZURE_SEARCH_INDEX_NAME`으로 지정한 인덱스에 직접 색인된다.
4. Data source, Indexer, Skillset이 생성되지 않아도 정상이다.
5. 초기 설정 자료는 `config-materials`, 신규 작성 첨부는 `uploaded-documents` 컨테이너에 저장된다.
6. `AZURE_COSMOS_ENABLED=true`이면 case와 설정은 Cosmos DB에 저장된다.
7. `AZURE_COSMOS_ENABLED=false`이면 case와 설정은 `data/database.json`에 저장된다.
8. Azure OpenAI의 구조화된 결과가 생성 폼에 표시된다.

증적: 연결 확인, Azure Portal 저장 결과, 생성 결과
